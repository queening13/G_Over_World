# G-Over World — 재현 가이드

구식 CGI 게시판 게임 양식(judomst.net 계열)의 **MS 파일럿 육성 시뮬레이션**.
FF ADVENTURE 계열 **2d6 대항판정**으로 전투를 굴리고, 기체 제원·무장·이미지·**지형 적성**은
**GGen Eternal Database** 공개 API에서 가져온 실제 데이터를 쓴다.

전투는 **전장(우주·공중·지상·수상·수중) → 교전 거리(1~20) → 색적 → EN** 순으로
상황이 잡히고, 각성 800 이상이면 **미래 예측**이 발동한다.

수록 기체 **1244기 전부**. 결과물은 `docs/` 폴더 하나(약 134MB)이고,
그대로 **GitHub Pages 나 Vercel 에 올리거나** 로컬에서 `index.html` 을 열어 실행한다.
외부 의존은 Google Fonts 스타일시트뿐이며, 실패해도 시스템 폰트로 대체된다.

## 1. 5분 재현

빈 디렉터리에 `build.mjs`, `serve.mjs`, 그리고 `src/` 의 다섯 파일
(`head.html` `engine.js` `ui.js` `i18n.mjs` `fetch-roster.mjs`)을 놓은 뒤:

```bash
node src/fetch-roster.mjs
```

```bash
node build.mjs
```

```bash
node serve.mjs
```

`http://localhost:8788/` 로 접속하면 끝. 수집은 1244기 기준 **약 5분**
(상세 1244건 + 이미지 2488장 / 142MB)이고, 빌드는 즉시 끝난다.

빠르게 확인만 하려면 등급별 3기씩만 받는다:

```bash
node src/fetch-roster.mjs --limit=3 && node build.mjs
```

> **로스터 수집은 결정적(deterministic)이다.** 선정 로직에 난수를 쓰지 않으므로
> 같은 API 상태에서 두 번 돌리면 `src/roster.json` 이 바이트 단위로 동일하게 나온다.

## 2. 요구 사항

| 항목 | 버전 / 비고 |
|---|---|
| Node.js | **18 이상** (전역 `fetch` 필요). 검증 환경은 v20.15.0 |
| 인터넷 | 최초 로스터 수집 때만. 이후 빌드·실행은 오프라인 가능 |
| 브라우저 | 최신 Chrome / Edge / Firefox. `localStorage` 사용 |
| 디스크 | 약 150MB (초상화 133MB + 썸네일 9.3MB + 나머지) |
| sharp | **선택.** `--resize` 로 초상화를 줄일 때만 필요 (`npm i -D sharp`) |

**필수 패키지 의존성은 없다.** 원본 해상도를 그대로 쓰면 `npm install` 자체가 불필요하다.

## 3. 디렉터리 구조

```
.
├── build.mjs              조각들을 docs/index.html 로 합침
├── serve.mjs              docs/ 를 정적 서버로 띄움 (Pages 와 같은 조건)
├── package.json           npm run fetch / build / serve
├── vercel.json            Vercel 배포 설정 (outputDir·캐시 헤더)
├── README.md              이 문서
├── docs/                  ← 배포 대상. 통째로 GitHub Pages 에 올린다
│   ├── index.html         0.91MB — 코드 + 1244기 데이터 인라인
│   ├── img/               초상화 936x803 · 1244장 · 133MB
│   ├── th/                썸네일 128x128 · 1244장 · 9.3MB
│   └── .nojekyll          Jekyll 처리 비활성화
└── src/
    ├── fetch-roster.mjs   GGen DB API → roster.json + docs/img · docs/th
    ├── i18n.mjs           빌드 시점 한글화 사전 (무장·특성·시리즈)
    ├── roster.json        기체 1244기 데이터 (0.95MB, 이미지는 경로만)
    ├── head.html          <title>·CSS·마크업 골격 + <script> 여는 태그
    ├── engine.js          상수 / 세이브 / 파생수치 / 전투 엔진
    └── ui.js              렌더링 / 화면 9종 / 이벤트 바인딩 / 부팅
```

### 왜 조각으로 나눠 두는가

`roster.json` 이 0.95MB라 통짜 HTML을 직접 편집하면 에디터가 느려지고, 게임 로직
한 줄 고칠 때마다 거대한 데이터 블록을 스크롤해야 한다. 데이터와 코드를 분리해
두면 로직만 편집하고 `node build.mjs` 로 합친다.

### 결합 순서 (build.mjs)

```
head.html                    ← <!DOCTYPE> ~ <script> "use strict";
  + "const UNITS = " + roster.json + ";"
  + engine.js
  + ui.js
  + "</script></body></html>"
```

`ui.js` 맨 끝의 `renderAll()` 이 부팅을 담당하므로 **engine → ui 순서를 지켜야 한다.**

이미지는 HTML 에 들어가지 않는다. `docs/img/` · `docs/th/` 에 개별 파일로 있고
HTML 에는 `img/1001000150.webp` 같은 **상대경로만** 들어간다.

## 4. 데이터 파이프라인

### 4.1 API 개요

베이스: `https://ggendb.up.railway.app`
인증 없음. JSON. 언어는 `lang=` 로 지정하며 **EN / TW / HK / JP** 만 지원한다
(한국어 없음 → 기체명은 영문, UI만 한글).

#### 목록 — `GET /api/units`

```
/api/units?lang=EN&page=1&per_page=100&grid_skills=1
```

| 파라미터 | 설명 |
|---|---|
| `page` | 1부터 |
| `per_page` | **서버가 100으로 자른다.** 200을 넣어도 100만 온다 |
| `sort` / `dir` | `rarity` 등, 선택 |
| `q` | 이름 검색, 선택 |

응답은 래퍼 객체이고 실제 유닛 배열은 **`rows`** 에 들어 있다.
`total`(1244), `total_pages` 를 보고 순회할 것.

`rows[]` 항목:

| 필드 | 예 | 설명 |
|---|---|---|
| `id` | `"1001000150"` | 상세 조회 키 |
| `name` | `"Gundam (EX)"` | 표시명 |
| `rarity` | `N` `R` `SR` `SSR` `UR` | 등급 |
| `role` | `Attack` `Defense` `Support` | 역할 |
| `HP` `ATK` `DEF` `MOB` `EN` `MOV` | 151599 / 10886 / 10040 / 8978 / 399 / 5 | 제원 |
| `thum` | `https://…github.io/…/thum_g0010u00150.webp` | 썸네일 URL (44px용, 미사용) |
| `grid_abilities[]` | `{name, detail, icon}` | 특성 요약 |

#### 상세 — `GET /api/unit/<id>`

```
/api/unit/1001000150?lang=EN
```

목록에 없는 것들이 여기 있다:

| 필드 | 설명 |
|---|---|
| `model` | `"RX-78-2"` 형식번호 |
| `series[]` | `{id, name, icon}` — `[0].name` 이 작품명 |
| `portrait` | **기체 초상화 URL.** 이 프로젝트가 쓰는 이미지 |
| `is_large` | 대형기 여부 |
| `abilities[]` | `{display_name, details:[{text}], icon}` |
| **`weapons[]`** | 아래 참조 |

`weapons[]` 항목:

| 필드 | 설명 |
|---|---|
| `name` | 무장명 |
| **`levels[]`** | `{level, power, en, ammo, accuracy, critical}` — **레벨별 위력표.** 무장 강화 시스템의 근거 |
| `power` `accuracy` `critical` | 대표값 |
| `en_cost` `ammo` | 소모 자원 |
| `min_range` `max_range` | 사거리 |
| `attribute` | `"Beam"` `"Physical"` 등 |
| `attack_types[]` | `{key:"melee"\|"shooting", label}` |
| `is_map` `is_ssp_weapon` `is_preemptive` | 분류 플래그 |

> 다른 URL 형태(`/api/units/<id>`, `/api/unit_detail?id=`)는 **404**다.
> 단수형 `/api/unit/<id>` 만 동작한다.

이미지는 별도 호스트(GitHub Pages)에 있다:
`https://zh7tcm9fmv-cloud.github.io/ggen_db_images/…`

**규격은 딱 두 가지뿐이고 중간 크기는 없다.**

| 경로 | 크기 | 용량 |
|---|---|---|
| `images/Trait/thum/thum_<code>.webp` | 작은 아이콘 | 약 8.8KB |
| `images/unit_portraits/ub_<code>.webp` | 936×803 초상화 | 약 140~226KB |

썸네일 URL에서 초상화 URL로 가는 규칙은 경로 중간만 바꾸면 된다:
`/Trait/thum/thum_` → `/unit_portraits/ub_`.
상세 응답의 `portrait` 필드에 완성된 URL이 이미 들어 있으므로 그쪽을 먼저 쓰고,
없을 때만 문자열 치환으로 만든다.

### 4.2 로스터 선정

기본은 **전 기체(1244기)** 다. 데이터만 보면 기당 740B 라 전부 담아도 0.92MB 밖에 안 된다.

```
UR 114 · SSR 350 · SR 365 · R 313 · N 102  =  1244기
```

`--limit=<n>` 을 주면 등급별로 `n` 기씩만 균등 간격으로 뽑는다. 개발 중 빠른
확인용이며, 앞에서부터 순서대로가 아니라 목록 전체를 훑는 간격 샘플이라
시리즈가 한쪽에 쏠리지 않는다.

### 4.3 저장 스키마

용량을 아끼려고 필드명을 짧게 줄인다. `roster.json` 은 이 객체의 배열이다.

```js
{
  id, nm,        // id, 이름 ('[SD] ' 접두어 포함)
  mdl, sr,       // 형식번호(model), 시리즈명(series[0].name)
  rar,           // 등급 — 화면에는 안 나온다. 적 편성 풀·EXP 계산용 내부 키
  hp,            // 원본 그대로 (상한 999,999)
  atk, def, mob, // 원본의 10%, 소수점 버림 (상한 9,999)  — #19 · #20
  en,            // 원본 그대로 (상한 999)
  sct,           // 색적 — 원 데이터에 없어 파생시킨 값 (상한 9,999)  — #11
  tr: { sp, ai, gr, se, uw },   // 지형 적성 0=× / 1=△ / 2=○        — #15
  lg,            // is_large
  w: [{          // 무장 (최종 레벨 위력 내림차순, 최대 6종)
    n,           // 이름
    pw: [ ... ], // 레벨별 위력 배열. pw[0]=Lv1, pw[len-1]=최대
    ac, cr,      // accuracy, critical
    en, am,      // EN 소모, 탄수 (0이면 무제한)
    mn, mx,      // 최소/최대 사거리 (표시용)
    at,          // 속성 "빔" / "실탄" / "특수" (한글화됨)
    tp,          // "M"=격투 / "S"=사격
    pre          // 선제 공격 플래그
  }],
  ab: [{ n, d }],// 특성 이름 + 설명(원문 160자까지 읽어 한글화)
  img,           // 'img/<id>.webp'  초상화 936x803 — 전투·도시에·도감 상세용
  th             // 'th/<id>.webp'   썸네일 128x128 — 목록·그리드용
}
```

`role`(공격형·방어형·지원형)과 `mov`(이동력)는 **저장하지 않는다.**
역할 구분은 게임에서 완전히 제거했고(#9), 이동력은 색적을 파생시킬 때만 쓰고
버린다(#11). 두 필드를 지우면 `roster.json` 이 약 20KB 줄어든다.

**맵 병기(`is_map`)와 SSP 전용 병기(`is_ssp_weapon`)는 제외한다.** 밸런스가
잡히지 않는 특수 무장이라 그대로 넣으면 수치만 망가진다.

**지형 적성 변환** — API 의 `terrain[].level` 은 3(●) / 2(▲) / 1(-) 이다.
게임 값은 `level − 1` 을 0~2로 clamp 한 것이라 **●=2 / ▲=1 / -=0** 이 된다.

### 4.4 이미지는 왜 분리하는가

한때 base64 로 HTML 에 내장했었다. 단일 파일이라는 장점이 있었지만 대가가 컸다.

| | 내장(base64) | 분리(파일) |
|---|---|---|
| 용량 | ×1.34 팽창 | 원본 그대로 |
| 지연 로딩 | 불가 — 전부 파싱 | `loading="lazy"` 로 보이는 것만 |
| 캐시 | HTML 통째로 | 파일 단위 |
| 상한 | Artifact 16MB | 없음 |

1244기를 내장하면 초상화 기준 **약 29MB** 라 아티팩트 상한을 넘고, 도감을 열
때마다 브라우저가 그 전부를 파싱해야 한다. 분리하면 첫 로딩은 `index.html`
0.86MB 뿐이고 이미지는 화면에 들어온 것만 내려간다.

#### 두 규격을 모두 받는 이유

호스트가 주는 규격은 딱 둘이다.

| 경로 | 크기 | 용량 |
|---|---|---|
| `images/Trait/thum/thum_<code>.webp` | 128×128 | 약 8.8KB |
| `images/unit_portraits/ub_<code>.webp` | 936×803 | 약 109KB |

도감 그리드는 44px 칸이다. 여기에 109KB 초상화를 쓰면 스크롤할 때마다 낭비가
크므로 **목록에는 썸네일, 상세·전투에는 초상화**를 쓴다. 경계는 썸네일 해상도가
버티는 지점(128px)에서 갈랐다.

```js
// src/ui.js
const picFor = (B, cls) => (cls === 'l' || cls === 'xl') ? B.img : (B.th || B.img);
// .s 44px · .m 72px  → 썸네일
// .l 104px · .xl 132px → 초상화
```

합계 142MB. `--resize=<px>` 를 주면 초상화를 줄일 수 있다(sharp 필요).

| 초상화 폭 | 기당 | 1244기 합계 |
|---|---|---|
| **원본 936px** | **109KB** | **133MB** |
| 512 | 약 45KB | 약 56MB |
| 288 | 약 24KB | 약 30MB |

### 4.5 한글화

API는 **EN / TW / HK / JP** 만 준다. 한국어가 없으므로 무장·특성·시리즈는
`src/i18n.mjs` 가 **빌드 시점에** 옮긴다. `roster.json` 에는 이미 한글이 들어가므로
런타임 비용은 0이다.

대상 규모(1244기 기준): 고유 무장 **1226종**, 특성명 **252종**, 특성 설명 **173종**, 시리즈 **103종**.

3단 구조로 처리한다.

1. **완전 일치 표** (`WEP_EXACT`) — 낱말로 쪼개면 망가지는 것. `Kick` → 킥,
   `Sekiha Tenkyoken` → 석파천귀권.
2. **구 치환** (`WEP_PHRASE`, `AB_PHRASE`) — `Beam Rifle` → 빔 라이플.
   **반드시 긴 키부터** 적용한다(`byLenDesc`). 짧은 키가 먼저 걸리면
   `Increased ATK & MOB` 이 `공격력 증가 & MOB` 처럼 반쪽만 번역된다.
3. **낱말 치환** (`WEP_TOKEN`) — 남은 단어. 구분자는 공백·괄호·슬래시만 쓴다.
   **하이픈으로 쪼개면 안 된다** — `Air-to-Air` 가 `공-to-공` 이 되어버린다.

특성 설명은 문형이 정해져 있어 정규식으로 옮긴다.

```
When HP is 75% or above, increase ATK by 20%.
  → HP 75% 이상일 때 공격력 20% 증가.
When enemies attack with a beam ranged weapon, reduce damage taken by 50%.
  → 적이 빔 사격 병장으로 공격할 때 받는 피해 50% 감소.
```

**형식번호·고유명은 일부러 영문으로 남긴다.** `MA-M01 Lacerta`, `RFW-99`,
`"Forfanterie"`, `Okitsu-no-Kagami` 같은 것을 억지로 음차하면 오히려 읽기 나쁘다.

최종 커버리지 — 시리즈 **103/103**, 특성명 **220/252**, 무장 **844/1226**.
무장 잔여 382건은 대부분 형식번호와 일본어 필살기명이다.

## 7. 게임 설계 명세

### 7.1 세이브 상태 (`g`)

`localStorage['gover.world.v4']` 에 JSON으로 통째 저장. 이미지·제원은 저장하지
않고 **`id` 만** 들고 있다가 `UMAP[id]` 로 참조한다. 세이브 크기는 수 KB.

```js
{
  name,                         // 파일럿명 (소속 개념은 없다)
  lv, exp, pt, cash,            // pt = 미배분 능력 포인트
  ap, apMax, day,
  mor0,                         // 전투 개시 기력 (100 + floor(정신/25), 이벤트로 상승)
  st: { sho, mel, def, rea, awk, spi },   // 사격·격투·수비·반응·각성·정신, 각 상한 999
  sk: [ '스킬키', ... ],        // 습득한 캐릭터 스킬 (CSKILL 이 비어 있으면 항상 빈 배열)
  kills, sorties, wins, losses, downs, fame,
  garage: [{
    id,                         // UNITS 의 id
    hp,                         // 현재 HP (출격 사이 유지)
    mod: { hp, en, def, mob, atk, sct },  // 각 0~10단
    wl: [ 1, 1, ... ],          // 무장별 레벨, 기체의 무장 수만큼
    pt: [ 'sp', 'uw' ]          // 장착한 지형 파츠 (최대 PART_SLOT = 2)
  }],
  cur,                          // garage 인덱스 = 탑승기
  records: [ {day, m, t, r, kills, pay, exp, hp} ],   // t = 전장 키. 최근 40건
  flags: { bossDown }
}
```

로드할 때 `UMAP[id]` 로 실재 여부를 검증하고, 없는 기체는 걸러낸다.
**로스터를 바꾸면 기존 세이브의 일부 기체가 사라질 수 있다.**
세이브 구조를 바꿨다면 `SAVEKEY` 의 버전을 올려 옛 세이브가 섞이지 않게 한다
(v3 → v4 에서 능력치 체계·소속·파츠가 전부 바뀌어 호환되지 않는다).

### 7.2 캐릭터 능력치

여섯 항목뿐이고 **상한은 999**, 레벨 상한도 999다.

| 키 | 이름 | 작용 |
|---|---|---|
| `sho` | 사격 | 사격 병장의 명중과 화력 |
| `mel` | 격투 | 격투 병장의 명중과 화력 |
| `def` | 수비 | 피탄 시 장갑 환산치 (구 '방어'와 같은 능력치, 이름만 바뀜) |
| `rea` | 반응 | 회피 · 거리 싸움 · 적 발견 |
| `awk` | 각성 | 각성 무장의 명중·회피·사거리, 그리고 미래 예측 |
| `spi` | 정신 | 전투 개시 기력과 기력 상승폭 |

구 '기량'은 폐지하고 **각성**으로 대체했다. 크리티컬 필요마진은 기량 대신
사격/격투에서 뽑는다([8.6](#86-크리티컬)).

**포인트 배분 (#4 · #6)**

```
생성 시     START_PT = 120 을 여섯 항목에 자유 분배 (잔여 0이어야 등록 가능)
레벨업 1회  LVUP_PT  = 5   포인트 지급 → 【훈련】에서 배분, 1 소모 = 1 상승
```

`LVUP_PT = 5` 는 의도적으로 모자라게 잡은 값이다.

```
2~999 레벨 = 998회 × 5 = 4,990 + 초기 120 = 5,110
6능력치 만렙 합계     = 6 × 999          = 5,994
```

**레벨업만으로는 전 능력치 999 를 채울 수 없다.** 모자란 884 이상은 훈련과
일일 이벤트로 메워야 하고, 훈련은 400 이상에서 성공률 1% 고정이므로
"무엇을 포기할지"가 육성의 실질적인 선택이 된다.

### 7.3 각성과 미래 예측 (#1)

**각성 무장** = 속성에 `특수` 가 들어간 병장 (`wIsAwk`). 전 로스터 3,259종 중 453종.

| 조건 | 효과 |
|---|---|
| 각성 0 | **각성 무장을 아예 쓸 수 없다.** 목록에 '사용 불가' 로 표시 |
| 각성 ≥ 1 | 각성 무장 사용 가능 |
| 각성 값 | 각성 무장 명중 `+floor(각성/100)`, 피격 회피 `+floor(각성/100)` |
| 각성 값 | 각성 무장 최대 사거리 `+floor(각성/100)`, **상한 `AWK_RANGE_CAP = 13`** |
| 각성 ≥ 800 | 매 판정 **5%** 로 미래 예측 발동 |

미래 예측은 판정 직전에 공격측·방어측 각각 굴린다(공격측 우선).

```
공격 턴에 발동 → 「거기냣!」  절대 명중 (크리티컬은 마진으로 따로 판정)
방어 턴에 발동 → 「보인다!」  절대 회피
```

발동 기준치는 **그 턴의 실효 각성치**로 본다.

```js
const awkOf = u => clamp((u.st.awk|0) + (u.awkTmp|0), 0, STAT_MAX);
```

`awkTmp` 는 장비·파츠·스킬·전투 중 효과가 얹는 일시 보정분이다. 지금은 늘 0이지만,
여기에 값을 넣기만 하면 "그 턴만 각성 800 을 넘겨 미래 예측이 뜨는" 연출이
별도 코드 없이 성립한다. 캐릭터 스킬을 붙일 때 쓸 자리다.

### 7.4 전장과 지형 적성 (#13~#16)

전장 5종: **우주 `sp` / 공중 `ai` / 지상 `gr` / 수상 `se` / 수중 `uw`**.
적성은 GGen API 의 `terrain[].level` 을 그대로 옮긴 것이다.

| API level | 심볼 | 게임 값 | 효과 |
|---|---|---|---|
| 3 | ● | 2 (`○`) | 제원 **100%** |
| 2 | ▲ | 1 (`△`) | **공격·기동 85%** |
| 1 | - | 0 (`×`) | **출격 불가** |

적 편성도 같은 규칙을 탄다. `buildFoes(ms, ter)` 는 그 전장에 적성이 있는
기체만 뽑고, 적성 △ 인 적기도 똑같이 85% 로 깎여 들어간다.

로스터의 적성 분포 — **전장 선택이 실제로 난이도를 바꾼다**:

| 전장 | × | △ | ○ |
|---|---|---|---|
| 우주 | 152 | 31 | 1,061 |
| 공중 | 885 | 40 | 319 |
| 지상 | 106 | 36 | 1,102 |
| 수상 | 1,200 | 0 | 44 |
| 수중 | 173 | 867 | 204 |

**수상은 ○ 가 44기(UR 1기)뿐이라 가장 척박하다.** 원 데이터가 그렇다.
반대로 수중은 867기가 △ 라 양쪽 다 85% 로 깎여 교전이 느슨해진다.

**지형 파츠 (#16)** — 기체당 슬롯 `PART_SLOT = 2`.

```
파츠 1개 = 해당 지형 적성 1단계 상승 (× → △ → ○)
같은 파츠 2개 = × 에서 ○ 까지 (슬롯 두 칸 소모)
비용 = round(시세 × 0.10 / 1000) × 1000,  탈거는 무상이나 환불 없음
```

이걸로 "수상 적성이 없어서 출격 자체가 막히는" 상황을 자금으로 풀 수 있다.

### 7.7 경제

기체 가격은 **등급이 아니라 제원 총합**에서 나온다(#18). 등급 표기를 지운
이상 값도 등급에서 뽑으면 안 되기 때문이다.

```js
uPow(B)  = B.hp*0.55 + (B.atk*3 + B.def*2.2 + B.mob*2.2 + B.sct*1.6)*22 + B.en*140
시세     = round(pow(uPow/1000, 1.6) * 90 * (대형기면 1.1) / 100) * 100
요구 Lv  = clamp(round((uPow − 100000) / 12000), 1, 40)
```

| 항목 | 공식 |
|---|---|
| 암시장가 | `시세 × (0.88 ~ 1.12)` — 날짜 시드로 고정된 흥정폭 |
| 매각가 | `시세 × 0.55` (개조·파츠 투자분 환불 없음) |
| 개조 비용 | `round(시세 × 0.045 × 1.34^현재단수 / 100) × 100` |
| 무장 강화 | `round(시세 × 0.05 × 현재레벨 / 100) × 100` |
| 지형 파츠 | `round(시세 × 0.10 / 1000) × 1000` |
| 정비 | `ceil((hpMax − hp) × 0.16 / 10) × 10` |
| 부대 유지비 | `1500 + 레벨 × 400` (다음 날마다) |
| 초기 자금 | `START_CASH = 80,000C` |

실제 값 — 최저 209,100C(요구 Lv2) · 중앙값 401,300C(Lv8) · 최고 1,127,200C(Lv22).

### 7.8 암시장 (#18)

  → 1~10기, 중복 없음, 무장 없는 기체 제외

**날짜만 알면 같은 매물이 나온다.** 하루 안에 화면을 몇 번 다시 그려도 목록이
흔들리지 않고, 세이브에 재고를 따로 담을 필요도 없다. 60일 평균 5.7기.

레벨별로 실제 살 수 있는 매물이 있는 날 (60일 기준):

| 레벨 | 매물 있는 날 | 일 평균 구입가능 기수 |
|---|---|---|
| Lv1 | 0 / 60 | 0.0 |
| Lv3 | 26 / 60 | 0.5 |
| Lv5 | 49 / 60 | 1.6 |
| Lv10 | 56 / 60 | 3.5 |
| Lv20 | 60 / 60 | 5.7 |

Lv1 에 아무것도 못 사는 것은 의도다(최저 요구 Lv 가 2). 초계 임무 한 번이
약 33,000C·40EXP 를 주므로 하루면 Lv3 대에 올라선다.

### 7.9 성장

```js
expNeed(lv) = round(100 × lv^1.45)     // LV_MAX = 999
```

레벨업 시: **능력 포인트 +5**, 자금 +4,000C, **4레벨마다 AP 상한 +1**
(시작 10 — `AP_BASE` 상수). 임무·훈련 양쪽에서 EXP가 들어온다.

계급은 격추수로만 결정: 훈련병 0 / 소위 3 / 중위 10 / 대위 24 / 소령 45 /
중령 75 / 대령 115 / 준장 170.

### 7.10 훈련 판정 (#7)

**능력치 상한은 없다(999 까지).** 대신 구간별로 성공 확률이 계단식으로 떨어지고,
**400 이상은 1% 고정**이다. 2d6 이 아니라 d100 직접 판정이다.

| 현재 능력치 | 성공률 | 성공 시 상승 |
|---|---|---|
| 0 ~ 49 | 90% | +4 |
| 50 ~ 99 | 70% | +3 |
| 100 ~ 149 | 50% | +3 |
| 150 ~ 199 | 35% | +2 |
| 200 ~ 249 | 22% | +2 |
| 250 ~ 299 | 14% | +1 |
| 300 ~ 349 | 8% | +1 |
| 350 ~ 399 | 4% | +1 |
| **400 이상** | **1%** | +1 |

```
EXP = 18 + 상승치 × 12   (실패해도 18)
AP  = TRAIN_AP = 1
```

400 이후 기댓값은 훈련 100회당 +1 이다. 여기서부터는 훈련이 아니라 레벨업
포인트와 일일 이벤트가 주 성장원이 된다.

### 7.11 캐릭터 스킬 (#8)

훈련 화면 하단에 **자금으로 사는 스킬 상점**이 있다. 구조는 완성되어 있고
목록만 비어 있다 — 항목을 넣으면 그대로 상점에 뜬다.

```js
const CSKILL = [
  // { k:'고유키', n:'표시명', c:비용, d:'설명' }

```

습득분은 `g.sk` 배열에 키로 쌓인다. 전투 보정을 붙이려면 `mkPlayer()` 에서

가중 추첨(총 가중치 100). 자금 획득/손실, HP 손상/완전정비, 능력치 +1,

## 8. 전투 규칙 전문

전투는 **완전 자동**이다. 플레이어의 개입 지점은 출격 전 **전장 선택 + 전법 선택** 둘뿐.

### 8.1 라운드 구조

최대 `ROUND_CAP = 24` 라운드. 한 라운드는 네 단계로 진행한다.

```
1) EN 회복 ─ 전 유닛 EN += ceil(enMax × EN_REGEN)      // 10% (#23)
2) 거리 싸움 ─ 교전 거리(1~20) 를 재조정                 // (#12)
3) 색적 ─ 시야에서 사라지거나 다시 잡아낸다                // (#11)
4) 행동 ─ 생존 유닛이 이니셔티브 순으로 1회씩
```

**행동 순서(이니셔티브):**

```
MOB + 색적 × 0.6 + (선제 병장 보유 시 900) + d6 × 320
```

내림차순, 매 라운드 다시 굴린다. 단 **1라운드만은 전투 개시 색적 판정에서
이긴 쪽이 먼저** 움직인다(선공권).

**표적 선택:** 플레이어는 HP 비율이 낮은 적을 우선하되 `±0.225` 난수로 흔든다.
**숨은(로스트) 상대는 후보에서 빠진다.**

**병장 선택:** `명중확률 × 예상피해` 가 최대인 것을 자동으로 고른다.
EN 부족·탄약 소진·**현재 거리 밖**·**각성 0인데 각성 무장** 은 후보에서 빠진다.

**화면 표시:** `paintDuel()` 이 공격기와 피격기의 초상화를 좌우로 크게 띄우고
가운데에 `교전 → HIT/CRITICAL/MISS + 피해량`, 미래 예측 시 대사를 찍는다.
`paintBoard()` 가 양쪽 전 유닛의 **HP·EN 게이지**를 갱신하고, 상단 `#dist` 가
전장명과 교전 거리 막대를 그린다. 넷 다 `S.duel`/`S.board`/`S.dist`/`S.blog` 에
보관되므로 전투가 끝나고 결과 화면을 다시 그려도 기록이 남는다
([11.5](#115-전투-종료-시-로그가-사라진다) 참조).

### 8.2 거리 (#12)

무장 사거리보다 **넓은 개념**이다. `DIST_MIN = 1` ~ `DIST_MAX = 20`,
전투 진입 시 `rint(1, 20)` 으로 무작위 지정.

원 데이터의 사거리는 1~5뿐이라 그대로 쓰면 거리 6 이상에서 아무도 못 쏜다.
`RANGE_MUL = 2` 로 거리축에 편다.

```js
mn = max(1, w.mn * 2 − 1)
mx = max(mn, w.mx * 2)
각성 무장이면 mx = min(13, mx + floor(각성/100))
```

결과적으로 격투는 1~2, 사격은 최대 6~10, 각성 무장은 최대 13까지 닿는다.

**거리 조정** — 매 라운드 양쪽이 희망 방향을 정한다.

| 상황 | 희망 |
|---|---|
| 나는 닿고 상대는 못 닿는다 | **0 (유지)** — 이 사거리를 최대한 지킨다 |
| 내 사거리 밖이다 | 자기 사거리 구간 쪽으로 (−1 접근 / +1 이탈) |
| 둘 다 닿는다 | 자기 구간 안이면 유지 |

```
방향이 같으면   step = 방향 × (1 + floor((내속도 + 적속도) / 4))   // 서로 달려든다
방향이 다르면   2d6 + 속도 대항판정, 이긴 쪽 방향으로
                step = 방향 × (1 + floor(|차이| / 4))
속도 mvSpd(u) = clamp(2 + floor(MOB/300) + floor(반응/120), 2, 9)
```

**공격 수단이 없는 쪽은 수비를 희생한다(`desperate`).**

```
거리 판정 굴림 +2   (필사적으로 사거리를 잡으러 간다)
회피 −2 · 받는 피해 +12%
```

### 8.3 색적 (#11)

`sct` 는 원 데이터에 없는 능력치다. 수집 단계에서 파생시킨다.

```js
sct = min(9999, round(MOB*0.55 + EN*0.9 + MOV*30))   // fetch-roster.mjs
```

| 국면 | 판정 |
|---|---|
| 전투 개시 | `2d6 + spotBon` 대항 → 이긴 쪽이 **선공권** |
| 시야 이탈 | `clamp(0.08 + (hideBon − 상대 spotBon) × 0.03, 0.02, 0.38)` |
| 재포착 | `2d6 + 탐색측 spotBon` vs `2d6 + 은신측 hideBon` |
| 명중 보정 | `clamp(floor((공격 색적 − 방어 색적) / 250), −3, +3)` |

```js
spotBon(u) = floor(색적/100) + floor(반응/40)
hideBon(u) = floor(MOB/220) + floor(반응/40)
```

**숨은 유닛은 때릴 수 없다.** 다만 **공격하면 그 즉시 위치가 드러난다**
(`A.hidden = false; A.exposed = true`) — 그리고 `exposed` 인 라운드에는
다시 숨을 수 없다. 이게 없으면 기동 높은 기체가 영구히 숨어 전투가 성립하지 않는다.

### 8.4 EN (#23)

```
매 라운드 시작 : EN += ceil(enMax × 0.10)
병장 사용      : EN −= w.en
EN 0           : 어떤 병장도 사용 불가 (usable() 이 즉시 false)
```

EN 게이지는 전투판·교전 표시부·좌측 패널 모두에 **주황색**으로 뜬다(#24).
고연비 병장만 든 기체는 실제로 중간에 손이 묶인다.

### 8.5 명중 판정

```
공격측 = floor(사격|격투 / 6) + 기력보정 + 전법보정
       + round((무장명중 − 100)/8) + 색적차 + (각성무장이면 floor(각성/100))

방어측 = floor(반응 / 6) + 기력보정 + floor(MOB / 350) + 전법회피
       + (각성무장이면 floor(각성/100)) + (대형기면 −1) + (desperate 면 −2)

우열 = clamp(공격측 − 방어측, −6, +6)
명중 = (2d6 + 우열) ≥ 2d6
```

`STAT_HIT_K = 6` 과 `MOB_EVA_K = 350` 의 **비율**이 이 식의 전부다.
능력치가 0~999 로 넓어졌으므로 나눗수로 눌러야 하는데, 너무 세게 누르면
기체 기동(MOB)이 파일럿 능력을 압도해 명중률이 16% 까지 떨어진다
([함정 §11.12](#1112-능력치-스케일을-바꾸면-명중식-비율이-무너진다)).

`clamp(±6)` 은 그대로 유지한다. ±6은 명중률 **11%~89%** 구간이다.

### 8.6 크리티컬

```
필요마진 = clamp(9 − floor(사격|격투/60) + floor(상대반응/90) − round(무장크리/5), 3, 12)
마진 ≥ 필요마진 → 크리티컬, 피해 ×1.45
```

구 '기량' 이 없어졌으므로 그 자리를 실제로 쏘는 능력치가 대신한다.

### 8.7 피해

```
공격력 = ATK × (1 + 사격|격투 × ATK_STAT_K) × 기력배율 × 전법
방어력 = DEF × (1 + 수비 × DEF_STAT_K) × (1 + (기력 − 100) × 0.002)

피해 = 무장위력 × (공격력 / 방어력) × DMG_K × 피격측전법
       × (피격측이 desperate 면 1.12)
       × (공격자가 적이면 FOE_DMG)
       × (방어측이 대형기면 1.06)

최소 200, 10단위 반올림
```

**`DEF_STAT_K` 를 `ATK_STAT_K` 보다 낮게 둔 것은 의도적이다.**
같게 두면 양쪽이 스탯을 올릴수록 서로 안 죽는 교착이 생긴다.

> 능력치 상한이 20 에서 999 로 바뀌면서 계수도 같이 내려갔다.
> `0.02 → 0.00167`, `0.018 → 0.0015`. 999 에서 각각 ×2.67 / ×2.50 이 되어
> 구 체계(20에서 ×1.40 / ×1.36)보다 성장 체감은 커지되 비율은 유지한다.

### 8.8 기력 (모랄)

```
morB(u) = clamp(floor((기력 − 100) / 10), −4, +5)   // 명중/회피 보정
morP(u) = 1 + (기력 − 100) × 0.005                   // 화력 배율 (150 → ×1.25)
```

| 사건 | 변화 |
|---|---|
| 공격 명중 | 공격측 **+1 + floor(정신/100)** |
| 피격 | 피격측 +2 |
| 회피 성공 | 회피측 +1 |
| 격추 달성 | 공격측 +3 |
| 아군 격추당함 | 같은 편 생존자 전원 +5 |

범위 50~150. 전투 개시 기력은 `100 + floor(정신/25)` 로 시작한다.

### 8.9 적 유닛 생성

적 파일럿 능력치는 **플레이어 레벨이 아니라 실제 능력 총합**을 따라간다.
포인트 자율 분배 때문에 같은 레벨이라도 실력 차가 크기 때문이다.

```js
base = max(4, round(statTotal() / 6 × 0.92))
off  = round(base × (보스 1.45 / 에이스 1.10 / 잡졸 1.00))   // 사격·격투
eva  = round(base × (보스 1.05 / 에이스 1.00 / 잡졸 0.86))   // 반응
awk  = round(base × (보스 1.10 / 에이스 0.80 / 잡졸 0.40))
무장레벨 = clamp(1 + floor(레벨/5), 1, 5)

HP  = 기본HP  × FOE_HP[등급]                  // 잡졸 0.38 / 에이스 0.52 / 보스 0.88
ATK = 기본ATK × 임무난이도 × 지형계수 × (보스 1.45)
DEF = 기본DEF × (보스 1.15)
MOB = 기본MOB × 지형계수
EN  = 기본EN                                   // 매 라운드 10% 회복하므로 배수 불필요
기력 = 에이스·보스 110, 잡졸 100
```

**`off` 와 `eva` 를 분리한 것이 이 설계의 핵심 교훈이다.** 하나의 값으로 둘 다
굴리면 강한 적일수록 "절대 안 맞고 절대 안 빗나가는" 무적이 된다
([§11.2](#112-정예기가-무적이-되는-이유)).

**지휘기는 HP 가 아니라 화력으로 세운다.** HP 를 1.15배까지 올려 봤더니
24라운드 안에 결판이 안 나 무승부가 30% 까지 치솟았다. HP 를 0.88 로 되돌리고
ATK 를 1.45배로 올리자 무승부가 2~14% 로 떨어지고 패배가 실제로 나오기 시작했다.

보상:

```
자금 = 시세 × 0.05 × (보스 4 / 에이스 2 / 잡졸 1)
EXP  = (10 + 등급인덱스 × 26) × (보스 5 / 에이스 2.5 / 잡졸 1)
```

|---|---|---|---|---|---|---|
| `ptrl` | 초계 임무 | 1 | 1 | N·N·R 중 2기 | 0.80 | 9,000C |

| `RANGE_MUL` | 2 | 원 사거리 → 거리축 환산 배수 |
| `AWK_FORESEE` | 800 | 미래 예측 발동 하한 |
| `AWK_FORESEE_P` | 0.05 | 미래 예측 확률 |
| `AWK_RANGE_CAP` | 13 | 각성 무장 사거리 상한 |
| `START_PT` / `LVUP_PT` | 120 / 5 | 능력 포인트 |

### 9.2 기체 제원 규격 (#19~#22)

원 데이터의 공격·방어·기동은 **10%(소수점 버림)** 로 줄여서 담는다.
수집 단계에서 한 번만 하고, 이후로는 이 값이 원본처럼 취급된다.

```
공격력 3,780 → 378        상한 9,999
HP    그대로              상한 999,999
EN    그대로              상한 999
색적  파생값              상한 9,999
```

**피해식은 `ATK / DEF` 비율이라 균일한 10% 축소로는 아무것도 변하지 않는다.**
바뀌는 것은 명중식의 `floor(MOB / MOB_EVA_K)` 뿐이라 나눗수만 같이 옮기면 된다.

등급별 중앙값 (`fetch-roster.mjs` 가 마지막에 출력):

| 등급 | HP | ATK | DEF | MOB | EN | 색적 | 최고위력 | 무장수 |
|---|---|---|---|---|---|---|---|---|
| N | 39,568 | 415 | 376 | 396 | 184 | 503 | 3,960 | 2 |
| R | 48,700 | 511 | 465 | 485 | 219 | 584 | 4,080 | 2 |
| SR | 58,571 | 615 | 558 | 583 | 254 | 691 | 4,440 | 3 |
| SSR | 74,285 | 816 | 731 | 738 | 315 | 839 | 5,040 | 3 |
| UR | 100,155 | 1,062 | 953 | 1,002 | 417 | 1,049 | 6,480 | 4 |

**HP : ATK 비가 등급 전체에서 거의 일정하다.** 그래서
`무장위력 × (ATK/DEF) × K` 형태의 식 하나로 N부터 UR까지 비슷한 히트 수가 나온다.
**계수를 다시 잡아야 할 때는 이 표를 먼저 뽑아라.**

### 9.3 목표 승률

전장 × 임무별 50회 시뮬레이션. 각 임무를 **그 임무에 맞는 장비**
(해금 레벨, 해당 전장 ○ 적성기 중 등급 중앙값, 무장 Lv, 개조 단수)로 돌렸다.
전법은 통상.

| 임무 | 우주 | 지상 | 공중 | 수중 | 수상 |
|---|---|---|---|---|---|
| 초계 임무 | 82% | 96% | 76% | 100% | 86% |
| 소탕전 | 80% | 68% | 74% | 92% | 58% |
| 거점 공략 | 58% | 56% | 48% | 78% | 68% |
| 에이스 요격 | 56% | 50% | 52% | 58% | 26% |
| 결전 · 기함 요격 | 68% | 68% | 74% | 42% | 36% |

무승부는 전 구간 14% 이하다. 장비가 한 단계 뒤처지면 승률이 급락한다 —
결전을 SSR 로 들어가면 **0%**, UR 로 들어가면 56~70%. 이게 암시장에서
기체를 갈아타야 할 이유다.

**수상·수중이 튀는 것은 원 데이터의 적성 분포 때문이다**([7.4](#74-전장과-지형-적성-1316)).
수상은 ○ 기체가 44기뿐이라 플레이어 기체가 약하고, 수중은 양쪽 다 △ 라
공격·기동이 함께 깎여 초·중반이 느슨해진다. 밸런스 문제가 아니라
**전장 선택이 실제 전략이 된다는 뜻**이다.

### 9.4 전법 균형

거점~요격 구간 기준. 지배 전략이 없도록 맞췄다.

| 전법 | 보정 | 성격 |
|---|---|---|
| 신중 | 명중 +2 / 화력 −10% / 피해 −18% | 안정적, 장기전 |
| 통상 | 없음 | 기준선 |
| 회피 | 회피 +4 / 화력 −18% / 피해 −12% | 패배가 적은 대신 무승부가 는다 |
| 맹공 | 명중 −2 / 화력 +22% / 피해 +28% | 빠르지만 대파 위험 |

> 초안에서는 맹공이 압도적이었다. 화력을 1.28→1.22로 낮추고
> 피격 배수를 1.10→1.28로 올려 위험을 실제 비용으로 만들었다.

## 10. 밸런스 검증 시뮬레이터

상수를 만졌다면 반드시 돌려볼 것. **Node 의 `vm` 으로 `src/engine.js` 를 그대로
실행한다.** 게임의 실제 함수(`runBattle`, `mkPlayer`, `buildFoes`, `hitAdv`,
`calcDmg`)를 그 자리에서 호출하므로 수식 중복이 없고, 세이브도 건드리지 않는다.

> 브라우저 콘솔에 붙여넣는 방식은 쓰지 않는다. **배경 탭에서 `setTimeout` 이
> 1초로 throttle 되어** 한 전투에 수십 초가 걸리기 때문이다
> ([§11.6](#116-배경-탭에서-settimeout-이-throttle된다)).

**`sim.mjs`** — 엔진을 DOM 없이 올린다.

```js

import path from 'node:path';

  UNITS: JSON.parse(fs.readFileSync(path.join(ROOT, 'src/roster.json'), 'utf8')),

  localStorage: { getItem: () => null, setItem: () => {}, removeItem: () => {} },
  setTimeout: (f) => { f(); return 0; },           // 연출 대기를 0으로

  confirm: () => true, window: {}
});
vm.runInContext(fs.readFileSync(path.join(ROOT, 'src/engine.js'), 'utf8'), ctx,
                { filename: 'engine.js' });
export { vm };
```

**`run.mjs`** — 전장 × 임무별 승률표.

```js
import { ctx, vm } from './sim.mjs';
const R = c => vm.runInContext(c, ctx);

/* 레벨에 맞는 표준 파일럿 — 초기 120pt + 레벨업 5pt/레벨을 여섯 능력에 고르게 */
function setup(lv, uid, wl, ter, mods) {
  R(`(function(){
    const tot = START_PT + (${lv}-1)*LVUP_PT, per = Math.floor(tot/6), st = {};
    STK.forEach(k => st[k] = per); st.sho += tot - per*6;
    newGame('t', st, ${JSON.stringify(uid)}); g.lv = ${lv}; g.pt = 0;
    const v = cur(); v.wl = v.wl.map(()=>${wl});
    if (${mods|0}) Object.keys(MOD).forEach(k => v.mod[k] = ${mods|0});
    v.hp = uStat(v).hpMax;
  })()`);
}
/* 그 전장에 ○ 적성이 있는 기체 중 성능 중앙값 */
const unitFor = (rar, ter) => R(`(function(){
  const p = UNITS.filter(u => u.rar===${JSON.stringify(rar)} && u.w.length
                           && adaptBase(u, ${JSON.stringify(ter)}) === 2);
  return p.sort((a,c)=>uPow(a)-uPow(c))[Math.floor(p.length/2)].id })()`);

const PLAN = [['ptrl',1,'N',1,0], ['swp',4,'R',2,0], ['base',8,'SR',3,1],
              ['itcp',14,'SSR',4,2], ['final',20,'UR',5,3]];
const N = 50;

for (const ter of ['sp','gr','ai','uw','se']) {
  console.log('\u25a0 ' + R(`TERRAIN[${JSON.stringify(ter)}].n`));
  for (const [mid, lv, rar, wl, mods] of PLAN) {
    const uid = unitFor(rar, ter);
    let w=0, l=0, d=0, hp=0;
    for (let i = 0; i < N; i++) {
      setup(lv, uid, wl, ter, mods);
      R('S.skip = true');                      // runBattle 은 시작 시 S.skip 을 false 로 되돌린다
      await R(`runBattle(MISSION.find(m=>m.id===${JSON.stringify(mid)}),
                         'norm', ${JSON.stringify(ter)})`);
      const r = R('S.res.r');
      if (r === 'win') w++; else if (r === 'lose') l++; else d++;
      hp += R('Math.round(cur().hp / uStat(cur()).hpMax * 100)');
    }
    console.log('  ' + R(`MISSION.find(m=>m.id===${JSON.stringify(mid)}).n`).padEnd(14) +
      ` \uc2b9${String(Math.round(w/N*100)).padStart(4)}%` +
      ` \ud328${String(Math.round(l/N*100)).padStart(4)}%` +
      ` \ubb34${String(Math.round(d/N*100)).padStart(4)}%` +
      `  \uc794\uc5ecHP${String(Math.round(hp/N)).padStart(4)}%`);
  }
}
```

## 11. 함정 모음

실제로 밟은 것들. 다시 만들 때 여기서 시간을 아낄 수 있다.

### 11.1 `per_page` 가 100에서 잘린다

`per_page=5000` 을 넣어도 100건만 온다. `total_pages` 를 보고 순회하지 않으면
1244기 중 100기만 받고 "전체 UR 등급"이라는 엉뚱한 통계를 얻게 된다.

### 11.2 정예기가 무적이 되는 이유

가장 오래 잡아먹은 버그. 적 파일럿 능력치를 **하나의 값 `ps` 로 만들어
사격·격투·반응에 전부 넣었더니**, 레벨이 오를수록 보스가

- 플레이어를 향한 명중률 **100%**
- 플레이어에게 맞을 확률 **5%**

인 상태가 됐다. 강한 적일수록 공격과 회피가 **동시에** 좋아지니 당연한 결과다.
`off`(공격)와 `eva`(회피)를 분리하고, 정예 보너스를 공격 쪽에 몰아주고
회피 쪽은 +1만 주는 것으로 해결했다.

### 11.3 명중 우열에 상한이 없으면 교착한다

`hitAdv` 를 그대로 두면 고레벨에서 우열이 −13까지 벌어져 명중률이 0.8%가 된다.
양쪽 다 안 맞아서 20라운드 내내 아무 일도 안 일어나고 전부 무승부가 된다.
`clamp(±6)` 으로 11~89% 구간에 가둬야 전투가 성립한다.

### 11.4 무장 레벨 1 기준으로 계산할 것

밸런스를 잡을 때 `pw[len-1]`(최대 레벨) 기준으로 계수를 뽑았는데, 플레이어는
**Lv1으로 시작한다.** 실제 초반 화력이 예상보다 20% 낮아 첫 임무가 무승부로
끝났다. 시뮬레이터를 `wlv = 1`과 `5` 양쪽으로 돌리는 이유다.

### 11.5 전투 종료 시 로그가 사라진다

전투가 끝나면 결과 상자를 그리려고 `renderAll()` 을 부르는데, 이때
`viewBattle()` 이 빈 `#blog` 를 새로 만들어 **방금 본 42줄짜리 전투 기록이
통째로 날아간다.** 로그와 상황판을 `S.blog[]` / `S.board` 에 보관해 두고
`viewBattle()` 이 그걸 다시 뿌리도록 고쳤다.

### 11.6 배경 탭에서 `setTimeout` 이 throttle된다

전투 연출은 `sleep()` = `setTimeout` 기반이다. 브라우저가 **비활성 탭의
타이머를 1초 간격으로 늦추므로**, 탭을 뒤로 둔 채 자동 시뮬레이션을 돌리면
수십 배 느려져 타임아웃 난다. §10 시뮬레이터가 DOM·타이머를 전혀 안 쓰는
동기 루프인 이유가 이것이다.

### 11.7 이미지를 HTML 에 내장하면 규모가 막힌다

base64 내장은 단일 파일이라는 장점 대신 **×1.34 팽창 + 지연 로딩 불가 + 용량 상한**을
같이 가져온다. 110기까지는 괜찮았지만 1244기에서는 성립하지 않는다.
파일로 분리하면 세 문제가 한꺼번에 사라진다([4.4절](#44-이미지는-왜-분리하는가)).

거꾸로, **데이터를 별도 JSON 으로 빼서 `fetch` 하는 것은 하지 말 것.**
`file://` 에서 CORS 에 막혀 로컬 실행이 깨진다. 이미지는 `<img src>` 라 상대경로가
그대로 먹지만 `fetch` 는 다르다. 그래서 데이터는 HTML 에 인라인으로 둔다.

### 11.8 등급을 지울 때 남는 것

화면에서 등급(N·SR·UR)을 빼도 **가격·해금 레벨·적 편성 풀**이 등급을 키로 쓰고 있다.
표기만 지우고 `rar` 는 내부 키로 남겨 두는 편이 안전하다. 대신 등급 탭으로
쓰던 개발·도감 화면의 분류 수단이 사라지므로 **작품(시리즈) 필터로 갈아끼워야** 한다.

### 11.9 Artifact CSP 는 외부 리소스를 전부 막는다

아티팩트로 발행하면 **외부 이미지가 호스트 불문하고 차단**되고 `fetch`/XHR 도 막힌다.
조용히 실패해서 빈 칸만 보인다. 즉 "아티팩트는 두고 이미지만 깃허브에서 불러오기"는
불가능하다. 아티팩트를 쓰려면 base64 내장 + 16MB 상한(약 500기)을 받아들여야 하고,
그 이상은 GitHub Pages 같은 일반 정적 호스팅으로 가야 한다.

### 11.10 사전을 고쳤다고 이미지까지 다시 받지 말 것

한글화는 수집 시점에 적용되므로 사전을 고치면 재수집이 필요하다. 하지만 이미지는
바뀌지 않았다. `--skip-images` 를 주면 상세 API 만 다시 돌아 **1분**이면 끝난다.
이걸 모르면 매번 133MB 를 다시 받게 된다.

### 11.11 로스터를 늘리면 사전 커버리지가 무너진다

110기 → 1244기로 늘렸을 때 고유 무장이 223종 → 1226종이 되면서 번역률이
**48%로 떨어졌다.** 시리즈도 43종 → 103종이 됐다. 규모를 바꾼 뒤에는 반드시
커버리지를 다시 재고([4.5절](#45-한글화)) 사전을 보강할 것.

### 11.12 능력치 스케일을 바꾸면 명중식 비율이 무너진다

능력치 상한을 20에서 999로 올릴 때 명중식의 캐릭터 항만 `floor(stat/12)` 로
누르고 기체 기동 항은 비례해서 `floor(MOB/220)` 으로 옮겼다. 결과:

```
레벨 20 · 사격 40   → floor(40/12)  = 3
UR 기동 1,000       → floor(1000/220) = 4
```

**파일럿 능력치보다 기체 기동이 커져 버렸다.** 실측 명중률 16%, 무승부 70%.
`floor(stat/6)` + `floor(MOB/350)` 으로 비율을 되돌리자 무승부가 0~2% 로 떨어졌다.

교훈 — **스케일을 바꿀 때는 개별 항이 아니라 항끼리의 비를 먼저 보라.**
`STAT_HIT_K` 와 `MOB_EVA_K` 를 상수로 뽑아 둔 이유다.

### 11.13 거리 개념을 넣으면 무승부가 폭증한다

교전 거리를 1~20 무작위로 잡았더니 절반 이상의 전투가 "아무도 사거리에
닿지 않는" 상태로 시작했다. 양쪽이 각자 대항판정으로 1~3칸씩 좁히다 보니
20라운드 중 5~7라운드가 이동에만 쓰였다.

**양쪽이 같은 방향을 원할 때는 대항판정을 하지 않는다.** 서로 달려드는
상황이므로 속도를 합산해 한 번에 좁힌다.

```js
if (pDir === eDir) step = pDir * (1 + Math.floor((mvSpd(P) + mvSpd(fLead)) / 4));
```

이것만으로 평균 라운드가 17.4 → 10.3 으로 줄었다.

### 11.14 보스 HP 를 올리면 강해지는 게 아니라 안 끝난다

지휘기가 너무 쉬워서 HP 배수를 0.72 → 1.15 로 올렸다. 승률은 82%→56% 로
내려갔지만 **패배가 아니라 무승부가 늘었다**(0% → 30%). 라운드 상한 안에
깎아낼 수 없는 HP 덩어리가 됐을 뿐이다.

HP 를 0.88 로 되돌리고 대신 **ATK 를 1.45배**로 올리자 같은 승률에서
무승부가 2~14%, 패배가 22% 로 정상화됐다. **라운드 상한이 있는 전투에서
난이도는 HP 가 아니라 화력으로 올려야 한다.**

### 11.15 숨은 유닛이 영구히 숨는다

색적(시야 이탈)을 넣자 기동이 높은 기체가 매 라운드 은신 판정을 통과해
아무도 때릴 수 없는 상태가 이어졌다. **공격하면 위치가 드러나도록**
(`A.hidden = false; A.exposed = true`) 하고, `exposed` 인 라운드에는 다시
숨지 못하게 막아야 성립한다.

### 11.16 등급을 지웠으면 가격도 등급에서 뽑으면 안 된다

`PRICE = {N:38000, ... UR:990000}` 처럼 등급별 정가표를 쓰면 화면에서 등급을
지워도 **가격이 등급을 그대로 노출한다.** 제원 총합에서 뽑도록 바꿨다.

```js
uPow(B) = B.hp*0.55 + (B.atk*3 + B.def*2.2 + B.mob*2.2 + B.sct*1.6)*22 + B.en*140
시세    = round(pow(uPow/1000, 1.6) * 90 / 100) * 100
```

지수 1.6 은 가격 폭을 벌리기 위한 것이다. 선형으로 두면 N 228k ~ UR 548k 로
2.4배밖에 안 벌어져서 "비싼 기체를 사는 재미"가 나오지 않는다. 현재 4.1배.

### 로스터 규모

기본이 전 기체(1244기)다. 줄이려면 `--limit=<n>` (등급별 n기).

```bash

```

**1기당 데이터 약 760B + 이미지 118KB.** 데이터는 전부 담아도 1MB 미만이라
규모를 좌우하는 건 사실상 이미지뿐이다.

### 데이터만 다시 받기

제원 스키마(지형 적성·색적·능력치 배율)를 바꿨는데 이미지는 그대로일 때:

```bash
node src/fetch-roster.mjs --skip-images   # 이미 있는 이미지는 건너뛴다
node build.mjs
```

1244기 상세 조회에 3~5분 걸린다. 끝나고 **반드시 기수를 확인할 것** —
API 가 몇 건 실패하면 로스터가 조용히 줄어든다.

```bash
node -e "console.log(require('./src/roster.json').length)"   # 1244 여야 한다
```

### 특정 기체 찾기

전 기체를 담으므로 강제 포함 목록은 필요 없다. API 의 정확한 이름을 확인하려면:

### 임무 추가

`src/engine.js` 의 `MISSION` 배열에 항목을 넣는다. 상황실·출격 화면이 자동으로
순회하므로 UI 수정은 필요 없다.

{ id:'raid', n:'거점 습격', ap:3, lv:16, pool:['SSR','UR'], cnt:5,
  diff:1.08, pay:280000, exp:900, d:'적 보급 거점을 급습한다.' }

`ace:'UR'` 을 넣으면 마지막 1기가 에이스로, `boss:true` 를 함께 넣으면 지휘기로 바뀐다.
편성은 **선택한 전장에 적성이 있는 기체 중에서만** 뽑히므로 별도 설정은 없다.

`fetch-roster.mjs` 의 `TERKEY` 에서 기존 지형을 조합해 파생시켜야 한다.

파츠는 `TER_ORDER` 를 순회해 자동 생성되므로 따로 추가할 것이 없다.

const AWK_FORESEE   = 800;    // 발동 하한

.ui.s{width:64px;height:56px}     /* 전투판·도감 그리드 — 썸네일 */

### 기체명 접두어

`src/fetch-roster.mjs` 의 `NAME_PREFIX`. 기본값 `'[SD] '`. 빈 문자열로 두면 접두어가 사라진다.
로스터에 저장되는 값이므로 바꾼 뒤 **재수집이 필요하다.**

### 등급 표기를 되살리려면

`rar` 값은 데이터에 그대로 남아 있다(적 편성·EXP 계산에 쓰인다).
`src/ui.js` 에 아래를 넣고 원하는 위치에 끼우면 된다.

```js
const rtag = r => '<span class="rtag r' + r + '">' + r + '</span>';
```

등급색 `--n/--r/--sr/--ssr/--ur` CSS 는 `head.html` 에 아직 남아 있다.
다만 **가격은 등급이 아니라 제원에서 나오므로** 되살려도 값과 등급이
정확히 일치하지는 않는다([§11.16](#1116-등급을-지웠으면-가격도-등급에서-뽑으면-안-된다)).

### 능력 포인트 곡선

```js
const START_PT = 120;   // 생성 시 자율 분배
const LVUP_PT  = 5;     // 레벨업 1회당
```

`START_PT + (LV_MAX − 1) × LVUP_PT` 가 `6 × STAT_MAX` 를 넘지 않아야
"레벨업만으로는 만렙 불가"라는 설계가 유지된다. 현재 5,110 < 5,994.

### 일일 행동력

`src/engine.js` 의 `AP_BASE`(기본 10). 4레벨마다 상한이 1씩 오르는 규칙은
`gainExp()` 안에 있다.

### 언어 바꾸기

`fetch-roster.mjs` 의 `LANG` 을 `JP`/`TW`/`HK` 로. **한국어는 API가 지원하지 않는다.**
무장·특성·시리즈는 `src/i18n.mjs` 가 빌드 시점에 옮기고([4.5절](#45-한글화)),
UI 문자열은 `head.html`·`engine.js`·`ui.js` 에 한글로 하드코딩돼 있다.
`LANG` 을 바꾸면 사전 키가 안 맞으므로 사전도 함께 갈아야 한다.
`wIsAwk` 가 `'특수'` 를 문자열로 찾으므로 **속성 사전을 바꾸면 각성 무장 판정도 같이 손봐야 한다.**

### 세이브 호환

`SAVEKEY` 는 `'gover.world.v4'`. 상태 구조를 바꿨다면 `v5` 로 올려서
기존 세이브가 깨진 채 로드되지 않게 한다. `load()` 가 `UMAP[id]` 검증과
누락 필드 보정(`pt`, `sk`, `mod.sct`)을 하므로 로스터만 바뀐 경우는
없는 기체만 조용히 걸러진다.
